## Summary

The F0.1 foundation already contained the Brandista homepage, API-backed featured products and categories, product listing/detail routes, and URL-driven keyword/category/sort/pagination controls. This milestone preserves that implementation, adds an API-backed featured makers section, and fixes a confirmed pagination defect. Product-detail fetch errors can now be retried, stale requests are ignored after navigation, and the discovery interactions have regression tests using the documented B0.14 DTO shapes.

No approved SRS or separate F0.2 plan/acceptance file is present in either repository. The frontend uses `B0.14-api-contract.md` in the backend repository as the available endpoint/schema reference. Therefore this report cannot claim conformance to an unavailable SRS.

## Changes

- `src/app.tsx`
  - Homepage now displays up to three active makers from the verified `GET /brands` endpoint, with independent loading, empty, failure, and retry states.
  - Pagination now preserves the selected `page` query parameter. Previously the shared filter updater immediately removed it, so Next/Previous repeatedly loaded page 0.
  - Product details expose a retry action on load failure and clear old product/error state when the slug changes. Cleanup ignores results from requests belonging to an earlier slug.
- `src/styles.css`
  - Reuses the established maker-card title typography for the semantically nested featured brand headings.
- `src/app.test.tsx`
  - Added documented response fixtures local to the test (not presented as live inventory).
  - Added regression coverage for keyword search, category filtering, price sort, page 1 request, product detail navigation, and retry after a simulated detail API failure.
  - Resets browser history between component tests.

No backend code or dependencies were changed. No development fixture is used by the application API layer.

## Actual API contract used

The only discovery requests issued by the homepage/catalogue/detail views are:

- `GET {VITE_API_BASE_URL}/products?size=4` — homepage featured products.
- `GET {VITE_API_BASE_URL}/categories` — category discovery (the backend defaults to page 0, size 50).
- `GET {VITE_API_BASE_URL}/brands` — homepage shows the first three active makers from the documented paginated response.
- `GET {VITE_API_BASE_URL}/products?page={page}&size=12&sort={sort}[&keyword={keyword}][&categoryId={categoryId}]` — listing. Supported sorts are `default`, `price_asc`, `price_desc`; category IDs and keyword follow the B0.14 contract.
- `GET {VITE_API_BASE_URL}/products/{slug}` — product detail.

`VITE_API_BASE_URL` defaults to `http://localhost:8080/api/v1` and is configured in `.env.example`. Product pages consume the B0.14 paginated response shape (`content`, `page`, `size`, `totalElements`, `totalPages`) and product fields (`id`, `name`, `slug`, `description`, `brandId`, `brandName`, `categoryId`, `categoryName`, `price`, `currency`, `availability`).
