## B. Automated run details and diagnostics

The final automated results above were collected after the accessibility fixes. The added component test took two correction iterations before passing:

1. `npx vitest run src/app.test.tsx --reporter=verbose --pool=forks --maxWorkers=1` — **FAIL (exit 1)**; the test expected an exact accessible heading name that did not match the rendered line-break-normalized name. The matcher was narrowed to `/Good finds/`.
2. The same command — **FAIL (exit 1)**; the header and footer both contained “Our brands”, so the selector was ambiguous. The selector was scoped to the `Main navigation` landmark.
3. `npx vitest run src/app.test.tsx --reporter=dot --pool=forks --maxWorkers=1` — **PASS (exit 0)**; 1 test passed.
4. Final `npm test` — **PASS (exit 0)**; 4 tests passed.

The first full `npm test` immediately after adding the jsdom test produced no output for over 30 seconds and was interrupted with Ctrl+C (exit 1; cause undetermined). After the isolated test had warmed up, the complete suite exited successfully in 3.51 seconds. The unsuccessful run is not counted as a pass.

A first form check used browser automation’s programmatic value setter, which bypassed native constraint validation and attempted the localhost request. It returned the expected connection error because the backend was offline. Repeating the check with keyboard input demonstrated the registration minimum-length browser validation; no real credentials were used.
