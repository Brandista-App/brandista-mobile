# F0.7 Release Readiness Report

Date: 2026-10-14. Repositories audited: `brandista-mobile` and sibling `brandista-mvp`.

## Assessment

**BLOCKED for an end-to-end local brand demonstration. NOT READY for staging or public production.** Backend unit/integration tests and offline package build passed against H2 and the existing Maven cache. Frontend baseline checks passed before this change. The requested real local stack could not be started because Docker Desktop's Linux engine pipe was absent. No MySQL-backed API, authenticated customer journey, browser responsive matrix, or production environment could therefore be verified. No SRS was present in the checked-out repositories or the discovered `brandista-docs` repository (which is empty), so conformance to unstated acceptance criteria remains unverified.

## Changes implemented

- Backend enables explicit liveness and database-aware readiness health groups, exposes them publicly with status only, and tests both routes. This keeps dependency failure out of liveness while reporting it through readiness.
- Backend README now documents actual seven migrations, MySQL app-credential readiness caveat, safe diagnostics, and the health routes; removed stale statements that cart/catalogue functionality was absent.
- Frontend toolchain direct dependencies are pinned, Node engine requirements reflect the installed Vite/Vitest/jsdom engines, existing Prettier failures were fixed, and an ESLint Fast Refresh warning was removed by moving the auth hook/context out of the component module.
- Frontend README now describes implemented routes/integration, the provisional local API URL and limitations without representing illustrations or fixtures as live products.

## Security and configuration findings

- Tracked configuration includes `.env.example` placeholders only; `.env` is ignored. It must be populated locally with non-production passwords and a generated JWT key of at least 32 decoded bytes. Never commit credentials.
- Backend CORS uses a configured origin allowlist; set the exact frontend scheme/host/port. `localhost` and `127.0.0.1` are distinct origins. Frontend API URL is build-time `VITE_API_BASE_URL`, defaulting to `http://localhost:8080/api/v1`; this is local-only and must be overridden for deployment.
- Existing backend tests cover password non-disclosure, customer ownership, authorization and CORS configuration; broad external security scanning was not available/configured. Full `npm audit` passed at baseline only.
- Existing access tokens are short-lived and kept in frontend memory. No refresh/revocation mechanism, registration rate limit, email verification, payment provider, order service, inventory reservation or customer cart/profile cross-account UI is implemented.
- Public actuator endpoints reveal only status; readiness includes `db`, liveness does not.
