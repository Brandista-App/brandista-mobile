# Brandista F0.5 — Cart and Checkout

Date: 2026-10-14

## Result

**Cart MVP: implemented against the documented backend contract. Live integration: BLOCKED. Checkout/order placement: unavailable by backend design.** This milestone does not create an order, reserve inventory, or collect payment. The SRS was not present in the repositories inspected; frontend requirements were compared with existing milestone documentation and the B0.14 backend audit/contract.

F0.4 PR #4 had been merged to `main`. F0.5 work is on `codex/f0-5-shopping-cart-checkout`, based on the fetched `origin/main` commit `85819b7`. Backend files were not changed.

## Implemented

- Product detail add-to-bag uses the existing authenticated cart API and reports success only after the server accepts the item. Unavailable products (409), invalid quantity (400), authentication and service errors have clear messages. Guests are sent to sign-in with a return location.
- Cart reads server data, including server-calculated unit prices, line subtotals, overall subtotal, currency and availability. Empty and initial-loading states are explicit.
- Quantity edits are drafts until submitted; values are checked as positive 32-bit integers and a successful update replaces the UI with the returned server cart. This avoids issuing a request for each keystroke.
- Item removal uses the existing delete endpoint, then refreshes the cart from the server (the delete response has no content). Concurrent cart mutations are locked.
- Refresh and mutation errors retain the last displayed cart where possible and expose retry. Unavailable items are identified and can be removed.
- Checkout remains visibly disabled with an explanation. `/checkout` continues to redirect to `/cart`; no order or payment endpoint exists in the audited contract.

## Backend contract used

Base URL defaults to `http://localhost:8080/api/v1`, overridden by `VITE_API_BASE_URL`. Requests attach the in-memory CUSTOMER bearer token. Cart data is fetched on entry; a browser reload clears the current frontend token and requires sign-in again, after which the cart is fetched from the backend.

| Method | Path                                | Request                   | Response / behavior                                                                                                                                                              |
| ------ | ----------------------------------- | ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/customers/me/cart`                | Bearer token              | `{ id, items: [{ itemId, productId, productName, brandName, unitPrice, quantity, lineSubtotal, available }], subtotal, currency }`; creates/returns the current customer's cart. |
| POST   | `/customers/me/cart/items`          | `{ productId, quantity }` | Updated cart; 201 for new item or 200 for existing item.                                                                                                                         |
| PATCH  | `/customers/me/cart/items/{itemId}` | `{ quantity }`            | Updated cart with server-calculated totals.                                                                                                                                      |
| DELETE | `/customers/me/cart/items/{itemId}` | None                      | 204; frontend then reloads the cart.                                                                                                                                             |

The contract requires positive integer quantities and CUSTOMER authorization; ownership is determined by the authenticated customer. Known responses include 400 validation, 401 unauthenticated, 403 role denied, 404 missing/foreign item and 409 unavailable product. Product/cart DTOs do not supply an image URL, so existing CSS artwork remains a placeholder, not a product photograph. Backend CORS must allow the exact frontend origin through `CORS_ALLOWED_ORIGINS` (for example `http://localhost:5173`).

## Reproduction

From `D:\uzair-brandista\repositories\brandista-mobile`:

1. Install dependencies with `npm install`.
2. Copy `.env.example` to `.env.local` and set `VITE_API_BASE_URL=http://localhost:8080/api/v1` as needed.

5. For live cart verification, first restore the backend and MySQL environment, then sign in with a disposable CUSTOMER account and use product detail add-to-bag, `/cart` update, remove and reload actions. Do not use production customer data.
